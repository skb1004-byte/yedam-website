# 화면 규칙 — 태블릿·노트북 대응 방안

2026-08-08 · 실측 기반

---

## 1. 지금까지 쓰던 규칙 (코드에서 추출)

명문화된 적은 없고 `kiosk.css` · 각 페이지 `@media` 에 흩어져 있던 것을 모았다.

| 항목 | 규칙 | 근거 |
|---|---|---|
| 터치 표적 | 최소 **44×44px**, 키오스크는 더 크게 | kiosk.css 의 버튼·입력 최소 크기 |
| 본문 글씨 | **14px 이상**, 키오스크는 확대 | 키오스크 확대 스타일 |
| 이미지 | 잘리지 않게 컨테이너에 맞춤 | kiosk-home 배너 잘림 수정 이력 |
| 한 화면 | 검사·게임 화면은 스크롤 없이 다 보이게 | 두뇌놀이터 `height: calc(100vh - N)` 방식 |
| 정사각 셀 | `aspect-ratio` 대신 **`grid-auto-rows:1fr` + 고정 높이** | aspect-ratio 는 넓은 컨테이너에서 화면을 넘긴다 |
| 글자 크기 | 고정값 대신 `clamp(최소, vh단위, 최대)` | 두뇌놀이터 카드 글씨 |
| 판정 기준 | 화면 폭이 아니라 **포인터 종류 + 화면 크기** | 키오스크는 1024×768 이라 폭만 보면 데스크톱으로 잡힌다 |

**마지막 항목이 핵심이다.** 폭만 보면 태블릿(1024)과 키오스크(1024)와
작은 노트북(1366)이 뒤섞인다. 손가락이냐 마우스냐를 같이 봐야 한다.

---

## 2. 실측 — 지금 무엇이 깨지는가

10개 주요 화면 × 3가지 크기. iframe 으로 실제 렌더링해서 쟀다.

### 좋은 소식 — 가로 넘침 0건

30번의 측정에서 **가로로 삐져나온 화면이 하나도 없었다.** 폭 대응은
이미 되어 있다. 새로 만들 것이 아니라 **다듬는 작업**이다.

### 문제 ① 한 화면에 안 들어옴

| 화면 | 태블릿 세로 768×1024 | 태블릿 가로 1024×768 | 노트북 1366×768 |
|---|---|---|---|
| aipia/test.html | +747px | +1,038px | +1,186px |
| nice-timetable.html | +970px | +1,151px | — |
| mom-play.html | +438px | 정상 | 정상 |
| teacher-writing.html | 정상 | +222px | — |
| mom/test.html | 정상 | +114px | — |

`index.html`(+13,000px)은 원래 스크롤하는 회사 홈이라 문제가 아니다.

**가로 화면일수록 나빠진다.** 세로 768px 짜리 화면에서 검사 문항이
한 화면에 안 들어온다는 뜻이다. 노트북에서 가장 심하다.

### 문제 ② 작은 글씨

| 화면 | 14px 미만 요소 |
|---|---|
| aipia/test.html | 949 |
| nice-timetable.html | 122 |
| index.html | 95 |
| teacher-writing.html | 78 |
| teacher-hub.html | 25 |

⚠ **이 숫자는 부풀려져 있다.** 화면에 안 보이는(display:none) 요소까지
셌기 때문이다. 특히 aipia/test.html 은 모든 검사 화면을 한 파일에 담고
숨겨 두는 구조라 949 중 실제로 보이는 것은 훨씬 적다.
보이는 것만 다시 세려다 브라우저가 버거워져 중단했다. **재측정 필요.**
다만 순위(어느 화면이 심한가)는 유효하다.

### 문제 ③ 터치 표적이 작음

| 화면 | 44px 미만 |
|---|---|
| nice-timetable.html | 71 |
| index.html | 7~20 |
| teacher-meal.html | 11 |
| career.html | 10 |
| teacher-writing.html | 8 |

시간표 도구가 압도적이다. 표 안의 작은 셀·버튼이 많아서다.
마우스로는 되지만 **터치 태블릿에서는 오조작이 난다.**

## 3. 왜 지금 구조로는 안 되나

브레이크포인트가 **9개 파일에 25종**으로 흩어져 있다.

```
280 360 380 400 420 480 520 560 600 640 680 720 760 768
780 820 840 860 880 900 960 1023 1079 1080 1180
```

같은 뜻인데 파일마다 값이 다르다(760 · 768 · 780). 한 곳을 고치면
다른 곳이 어긋난다. 태블릿·노트북을 여기에 더 얹으면 감당이 안 된다.

## 4. 방안 — 공통 규칙 한 벌로 모으기

`kiosk.css` 가 키오스크에 한 일을 태블릿·노트북에도 한다.
**새 디자인이 아니라, 흩어진 규칙을 한 벌로 모으고 빈 구간을 채우는 것.**

### 4-1. 기기 판정 (kiosk.js 확장)

폭이 아니라 폭 + 포인터로 가른다. `<html>` 에 클래스를 붙인다.

| 클래스 | 조건 | 대상 |
|---|---|---|
| `dev-phone` | 폭 < 640 | 휴대폰 |
| `dev-tablet` | 640~1180 **AND 손가락** | 아이패드·갤탭 |
| `dev-laptop` | 1024~1600 **AND 마우스** | 노트북 |
| `dev-desktop` | ≥ 1600 | 데스크톱 |
| `kiosk-on` | 손가락 AND 긴 변 ≥ 900 | 키오스크 (기존 유지) |

키오스크 판정을 먼저 하므로 기존 동작은 그대로다.

높이도 본다. `screen-short`(높이 < 820) 를 붙여 "가로 태블릿·노트북"
처럼 세로가 모자란 상황을 한 클래스로 잡는다. 문제 ①이 여기서 난다.

### 4-2. 공통 스타일 `screen.css` (신규)

```
· 본문 최소 15px (태블릿) / 15px (노트북)
· 터치 기기의 버튼·입력·표 셀 최소 44px, 간격 8px 이상
· 이미지 object-fit: contain (잘림 금지) — 배너만 cover + 안전영역
· 한 화면 요구 화면: height: calc(100dvh - 헤더 - 하단)
  100vh 가 아니라 100dvh — 태블릿 브라우저 주소창 때문에 vh 는 어긋난다
· 정사각 셀은 grid-auto-rows:1fr (aspect-ratio 금지)
· 글자는 clamp(최소, vh기반, 최대)
```

### 4-3. 브레이크포인트 통일

25종 → **4종**(640 / 1024 / 1180 / 1600). 기존 값은 가장 가까운 것으로
옮기되, **한 파일씩** 옮기고 매번 실측한다. 한꺼번에 바꾸지 않는다.

### 4-4. 순서 (영향이 작은 것부터)

| 순서 | 대상 | 이유 |
|---|---|---|
| 1 | kiosk.js 기기판정 + screen.css 뼈대 | 아직 아무 화면도 안 바뀜 |
| 2 | nice-timetable.html | 터치 표적 71개로 가장 심함 |
| 3 | aipia/test.html | 세로 넘침 최대 · 매출 핵심 |
| 4 | mom-play · mom/test | 한 화면 요구가 큼 |
| 5 | teacher-* · career | 나머지 |
| 6 | 브레이크포인트 통일 | 위가 다 끝난 뒤 |

각 단계마다 **바꾸기 전후를 같은 방식으로 재서** 숫자로 확인한다.

## 5. 먼저 정해야 할 것

1. **글씨 최소값** — 14px(현행 기준) 인가 15px 인가 16px 인가.
   올릴수록 한 화면에 들어가는 양이 줄어 문제 ①과 부딪힌다.
2. **한 화면 원칙을 어디까지 적용할지** — 검사 문항은 당연하고,
   결과지·시간표까지 넣으면 글씨가 많이 작아진다.
3. **태블릿 세로를 지원할지** — 지금 키오스크는 가로 고정이다.
   세로까지 하면 레이아웃이 한 벌 더 필요하다.

---

## 6. 하지 않을 것

- 디자인을 새로 만들지 않는다. 지금 모양을 유지한 채 크기·배치만 맞춘다.
- 검사 문항·점수식·API·저장 구조는 건드리지 않는다.
- 한꺼번에 전 파일을 바꾸지 않는다. 되돌릴 수 있는 크기로 나눈다.
