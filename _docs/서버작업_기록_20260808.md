## 겪은 문제 네 가지

### 🔴 결과 API 를 몇 분간 죽였다 (내 실수)

자동 기동을 등록하면서 `Get-Process node | Stop-Process -Force` 를 돌렸다.
결과 API 도 node 로 돌기 때문에 **그것까지 같이 꺼졌다.**
확인 과정에서 발견해 `Start-ScheduledTask` 로 되살렸다.
프로세스를 이름으로 싸잡아 끄면 안 된다. 작업 스케줄러 단위로 다뤘어야 했다.

### `Restart-ScheduledTask` 가 없다

이 환경에는 그 명령이 없다. `Stop-ScheduledTask` → `Start-ScheduledTask` 로 갈랐다.

### 작업 스케줄러의 `-Execute 'node'` 가 안 뜬다

SYSTEM 계정 PATH 에 node 가 없다. 절대경로로 바꿔서 해결했다.

```powershell
-Execute 'C:\Program Files\nodejs\node.exe'
```

### PowerShell 5.1 은 BOM 없는 .ps1 을 ANSI 로 읽는다

한글 주석이 깨져 파서가 통째로 실패했다(`Unexpected token '???세뿔'`).
`utf8NoBOM` 도 5.1 에는 없다. 파일 앞에 BOM 3바이트를 붙여 해결했다.

```powershell
[IO.File]::WriteAllBytes($f, ([byte[]](0xEF,0xBB,0xBF) + $bytes))
```

1단계에서 겪은 BOM 문제와 방향만 반대다. **`.env` 는 BOM 이 있으면 안 되고,
`.ps1` 은 BOM 이 있어야 한다.**

## 남은 일

### 키 채우기 — 이게 되어야 프론트를 넘긴다

`C:\yedam\ai-proxy\.env` 가 아직 전부 비어 있다(`providers: []`).
그래서 프론트는 아직 Cloudflare Worker 를 보고 있고, 서비스는 정상이다.

| 키 | 비고 |
|---|---|
| `GEMINI_KEY` `GROQ_KEY` `CEREBRAS_KEY` `OPENROUTER_KEY` `HF_KEY` `GITHUB_KEY` | Worker Secret 은 값을 볼 수 없어 **전부 재발급** |
| `CAREERNET_KEY` | 값을 이미 안다. 이것만 넣어도 진로 기능은 넘어온다 |
| `DATAGO_KEY` `KOSIS_KEY` `NEIS_KEY` | 해당 기능 쓸 때 |

키를 채운 뒤 프론트 네 곳을 `https://api.yedam.kr/ai` 로 바꾼다.
`aipia/test.html` 2716 · 3317 · 5034 · `career.html` 103

**Worker 는 지우지 않는다.** 문제가 생기면 네 곳을 되돌리는 것만으로 복구된다.

### `INGEST_TOKEN` — 순서 주의

`POST /api/results` 는 아직 인증이 없다. 주소만 알면 가짜 결과를 넣을 수 있다.
프론트는 준비돼 있다(토큰이 있는 기기만 `x-ingest-token` 을 붙인다).

**키오스크에 먼저 넣고, 그다음 서버를 켠다.** 반대로 하면 그 기기의 저장이 막힌다.

```js
localStorage.setItem('pia_ingest_token','발급값');   // ① 키오스크 브라우저
```
```
INGEST_TOKEN=발급값                                   # ② C:\yedam\api\.env
```
